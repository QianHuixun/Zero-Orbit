# 开发计划：个人网站+博客

## 背景

本开发计划基于以下已确认文档：

- `personal-site-blog.md`：产品与内容需求。
- `ui-visual-direction.md`：黑暗高级、轻科幻、宇宙知识星图方向。
- `technical-selection.md`：Astro + React Islands + React Three Fiber + Tailwind CSS + MDX/Content Collections + Pagefind。

开发目标是在第一版中交付一个可写作、可阅读、可检索、首页有强视觉记忆点的个人网站+博客。

## 总体策略

- 先完成内容系统和静态页面骨架，保证博客核心可用。
- 再完成搜索、频道、归档、标签等检索能力。
- 最后实现首页宇宙知识星图和高级动态交互。
- 首页允许炫技，文章页和检索页保持稳定、清晰、快速。
- 每个阶段都应能独立验证，避免把风险集中到最后。

## 阶段 0：项目初始化

### 目标

建立 Astro 项目基础，配置 React、Tailwind、MDX 和基础目录结构。

### 任务

- 初始化 Astro 项目。
- 接入 React integration。
- 接入 Tailwind CSS。
- 接入 MDX。
- 建立基础目录结构：
  - `src/content/posts`
  - `src/data`
  - `src/layouts`
  - `src/components/astro`
  - `src/components/react`
  - `src/lib`
  - `src/styles`
- 建立全局样式入口。
- 建立基础设计变量文件。
- 配置 TypeScript。

### 交付物

- 项目可以启动开发服务器。
- 首页可显示最小 Astro 页面。
- Tailwind 样式可正常生效。
- React Island 可正常渲染一个测试组件。

### 验收标准

- `dev` 脚本可以启动本地开发环境。
- `build` 脚本可以完成构建。
- 页面没有基础运行错误。

## 阶段 1：内容模型与站点配置

### 目标

建立结构化内容源，为页面、搜索和首页星图提供统一数据。

### 任务

- 配置 Astro Content Collections。
- 定义文章 schema：
  - `title`
  - `summary`
  - `channel`
  - `tags`
  - `publishedAt`
  - `updatedAt`
  - `status`
  - `featured`
  - `cover`
  - `series`
  - `related`
- 建立频道配置 `channels.ts`：
  - 技术。
  - 产品/创造。
  - 阅读。
  - 生活随笔。
- 建立站点配置 `site.ts`：
  - 站点名。
  - 作者名。
  - 一句话介绍。
  - 当前关注。
  - 社交链接。
- 编写内容查询工具：
  - 获取已发布文章。
  - 获取精选文章。
  - 获取最新文章。
  - 按频道过滤文章。
  - 按标签聚合文章。
  - 按年份归档文章。
- 添加 4-8 篇示例文章，用于页面和搜索验证。

### 交付物

- 统一文章 schema。
- 频道和站点配置。
- 示例内容。
- 内容查询工具函数。

### 验收标准

- 无效文章字段会在构建时暴露错误。
- 草稿文章不进入公开列表。
- 精选、最新、频道、标签、归档数据能从同一内容源派生。

## 阶段 2：基础布局与静态页面

### 目标

实现博客的核心页面，让站点在没有复杂动效前已经可用。

### 任务

- 实现 `BaseLayout.astro`：
  - HTML 基础结构。
  - 全局导航。
  - 页脚。
  - SEO 基础 meta。
  - 深色主题背景。
- 实现 `ArticleLayout.astro`：
  - 文章标题。
  - 摘要。
  - 频道。
  - 标签。
  - 发布时间和更新时间。
  - 正文区域。
  - 前后篇入口。
  - 相关文章入口。
- 实现页面：
  - 首页基础结构。
  - 文章详情页。
  - 频道页。
  - 标签页。
  - 归档页。
  - 关于页。
- 实现 Astro 静态组件：
  - 导航。
  - 文章卡片。
  - 频道卡片。
  - 标签列表。
  - 归档列表。
  - 空状态。

### 交付物

- 可浏览的静态博客。
- 首页展示个人入口、频道、精选文章、最新文章和索引入口。
- 文章、频道、标签、归档、关于页可访问。

### 验收标准

- 所有页面可以通过导航互相到达。
- 文章页在不依赖客户端 JavaScript 的情况下可阅读。
- 频道、标签、归档页面只展示已发布文章。
- 空状态展示正常。
- 移动端基础布局不重叠。

## 阶段 3：视觉系统与响应式基础

### 目标

建立黑暗高级、轻科幻的基础视觉系统，为首页动效和内容页阅读奠定统一风格。

### 任务

- 定义 CSS 设计变量：
  - 背景色。
  - 文字色。
  - 边框色。
  - 强调色。
  - 辉光色。
  - 阴影。
- 配置 Tailwind theme 扩展。
- 实现基础组件视觉：
  - 按钮。
  - 标签。
  - 卡片。
  - 输入框。
  - 面板。
  - 链接。
- 实现文章正文排版样式。
- 实现深色滚动条和选择文本样式。
- 完成桌面端和移动端断点布局。

### 交付物

- 统一暗色视觉系统。
- 文章页、频道页、检索页的稳定基础样式。
- 首页下方内容区视觉完成。

### 验收标准

- 页面不呈现默认模板感。
- 深色背景下正文、链接、按钮对比度足够。
- 手机端按钮、标签、标题不重叠。
- 内容页不被过多装饰干扰。

## 阶段 4：Pagefind 搜索与命令面板

### 目标

实现站内搜索和命令面板式搜索体验。

### 任务

- 安装并配置 Pagefind。
- 调整构建脚本：Astro 构建后生成搜索索引。
- 为可搜索内容添加必要标记。
- 实现搜索页：
  - 搜索输入。
  - 搜索结果。
  - 无结果状态。
  - 频道/标签辅助筛选。
- 实现命令面板 React Island：
  - 点击搜索入口打开。
  - 支持键盘快捷键 `/` 打开。
  - 支持输入搜索。
  - 支持键盘上下选择结果。
  - 支持回车进入结果。
  - 支持 Esc 关闭。

### 交付物

- 可用的搜索页。
- 可用的命令面板搜索。
- Pagefind 搜索索引。

### 验收标准

- 能搜索文章标题、摘要和正文。
- 搜索结果展示标题、摘要、频道、标签和日期。
- 无结果状态清晰。
- 命令面板可用键盘完成基本操作。
- 搜索脚本不破坏静态构建。

## 阶段 5：首页宇宙知识星图

### 目标

实现首页首屏强冲击视觉：宇宙背景、知识核心、频道星体、标签星点和精选文章节点。

### 任务

- 安装 Three.js 相关依赖：
  - `three`
  - `@react-three/fiber`
  - `@react-three/drei`
- 建立首页星图组件结构：
  - `KnowledgeUniverse.tsx`
  - `UniverseCanvas.tsx`
  - `KnowledgeCore.tsx`
  - `ChannelPlanet.tsx`
  - `ArticleNode.tsx`
  - `StarField.tsx`
- 从内容层派生星图数据：
  - 频道 -> 主星体。
  - 标签 -> 小星点。
  - 精选文章 -> 轨道节点。
  - 文章数量与更新时间 -> 频道状态。
- 实现视觉层：
  - 深空背景。
  - 星尘粒子。
  - 中心知识核心。
  - 频道轨道。
  - 节点辉光。
- 实现交互层：
  - 鼠标视差。
  - Hover 频道高亮关联节点。
  - Hover 文章节点显示信息浮层。
  - 点击频道进入频道页。
  - 点击文章进入文章页。
- 实现首屏启动动画。
- 实现低频循环动画。
- 实现移动端降级版本。
- 实现减少动态效果偏好下的静态替代状态。

### 交付物

- 首页首屏宇宙知识星图。
- 可交互频道星体与文章节点。
- 桌面端强视觉冲击版本。
- 移动端简化版本。
- 动画降级策略。

### 验收标准

- 首页第一眼具备明确宇宙感和知识星图记忆点。
- 用户能从星图进入频道和精选文章。
- 星图不遮挡站点名、介绍和主要入口。
- 首屏启动动画控制在 1.5-2.5 秒左右。
- 动画结束后页面进入稳定低频状态。
- 移动端不卡顿，核心入口可用。
- 文章页不加载首页 3D 代码。

## 风险与应对

### 首页 3D 复杂度过高

- 应对：先实现静态可用首页，再加入 Three.js 星图。
- 应对：Three.js 组件只封装在首页 island 中。
- 应对：移动端使用简化粒子和节点数量。

### 搜索索引与构建流程冲突

- 应对：先完成 Astro 构建，再接 Pagefind。
- 应对：搜索页先做静态结构，再接真实索引。

### 深色视觉影响阅读

- 应对：文章页单独调正文排版、对比度和行高。
- 应对：首页强视觉不延伸到正文区域。

### 内容模型过早复杂化

- 应对：第一版只保留已确认字段。
- 应对：系列、封面、相关文章保持可选。

## 待确认事项

- 包管理器：建议使用 `pnpm`。
- 部署平台：建议优先考虑 Vercel 或 Cloudflare Pages。
- 首页 3D 第一版复杂度：建议先做可交互星图，不做过重后处理。
- RSS：建议第一版加入。
- 首批真实文章数量：建议至少 4 篇，每个频道 1 篇。
