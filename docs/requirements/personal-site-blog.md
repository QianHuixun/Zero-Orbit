# 需求文档：个人网站+博客

## 背景与目标

本项目旨在建设一个个人网站与博客，用作长期写作、主题沉淀和个人表达的空间。站点定位为个人“思想花园”，不是营销型个人主页，也不是纯作品集。

第一版重点是让内容能够被舒适阅读、清晰分类、方便检索，并为后续 UI 设计和技术实现提供稳定的需求基准。

### 目标

- 建立一个可长期维护的中文个人网站与博客。
- 通过主题频道沉淀技术、产品/创造、阅读、生活随笔等内容。
- 让自己可以方便回看文章、标签、归档和专题方向。
- 让朋友、同行或读者能快速了解站点主人、近期关注和代表性文章。
- 保持温馨轻松的整体气质，避免过度营销化或模板化。

## 目标用户与使用场景

### 目标用户

- 站点作者：用于长期写作、复盘、检索和积累个人知识。
- 熟人、朋友、同行：用于了解作者是谁、在关注什么、写过什么。
- 外部读者：通过文章、标签、频道或搜索进入内容。

### 使用场景

- 作者发布一篇结构化 Markdown 文章，并归入某个主题频道。
- 作者回看过去文章，通过关键词、标签、频道或归档快速找到内容。
- 读者从首页进入，先理解作者的个人气质和近期关注，再进入频道或文章。
- 读者从搜索引擎或外部链接进入文章页，再继续阅读相关文章或返回频道。

## 需求范围

### 第一版必须实现

- 首页作为个人入口。
- 四个主题频道：技术、产品/创造、阅读、生活随笔。
- 文章列表与文章详情。
- 结构化 Markdown 内容模型。
- 标签、频道、归档和站内搜索。
- 关于页，包含轻量个人化信息。
- 中文界面与中文内容支持。
- 响应式布局，覆盖桌面端与移动端。

### 第一版暂不实现

- 评论、点赞、用户账号等互动功能。
- 邮件订阅、通知、私信等触达能力。
- 后台管理系统。
- 双语界面或完整多语言内容管理。
- 访问统计后台、复杂推荐系统或内容商业化能力。

## 信息架构

### 首页

首页承担个人入口的角色，应让访问者快速理解站点主人、站点气质和主要内容方向。

首页应包含：

- 简短个人介绍。
- 当前近况或最近关注。
- 四个主题频道入口。
- 精选文章。
- 最新文章。
- 通往关于页、归档页和搜索入口的路径。

### 频道页

频道页用于承载主题化内容，帮助读者按兴趣进入文章。

第一版频道包括：

- 技术：工程实践、开发经验、工具、AI 相关技术思考。
- 产品/创造：产品思考、创作过程、项目复盘、个人工具构想。
- 阅读：读书笔记、摘录、书评、知识整理。
- 生活随笔：日常观察、个人感受、轻量记录。

频道页应展示频道说明、文章列表、标签筛选入口和空状态。

### 文章页

文章页优先支持检索和回看，同时保持舒适阅读体验。

文章页应包含：

- 标题、摘要、发布时间、更新时间。
- 所属频道与标签。
- 正文内容。
- 文章目录。
- 前后篇导航。
- 相关文章或同标签文章。
- 返回频道或归档的路径。

### 检索页

检索页用于帮助作者和读者快速找到内容。

检索页应支持：

- 关键词搜索。
- 标签筛选。
- 频道筛选。
- 归档入口。
- 无结果状态。

搜索结果应展示标题、摘要、频道、标签和发布时间。

### 关于页

关于页提供轻量个人化信息，避免变成冗长简历。

关于页应包含：

- 简短自我介绍。
- 当前关注或正在做的事。
- 最近在读或近期输入。
- 联系方式或社交链接。

## 内容模型

文章使用结构化 Markdown。每篇文章应包含以下字段：

- 标题。
- 摘要。
- 频道。
- 标签。
- 发布时间。
- 更新时间。
- 状态。
- 是否精选。

可选字段包括：

- 封面图。
- 系列名。
- 相关文章。

### 文章状态

第一版可支持以下状态：

- 已发布：公开展示。
- 草稿：不在公开页面展示。
- 归档：保留可访问性，但不作为重点内容展示。

## 页面与交互需求

### 导航

- 全站应提供清晰稳定的主导航。
- 访问者应能从任意页面进入首页、频道、归档、搜索和关于页。
- 移动端导航应保持易用，不遮挡正文阅读。

### 搜索与筛选

- 用户可以通过关键词搜索文章标题、摘要和正文内容。
- 用户可以点击标签查看同标签文章。
- 用户可以在频道页查看该频道下的文章。
- 用户可以通过归档按时间回看内容。

### 空状态

以下场景应有清晰占位说明：

- 暂无文章。
- 频道下暂无文章。
- 搜索无结果。
- 暂无精选文章。

## 视觉方向

整体视觉气质为温馨轻松、阅读友好、轻个人化。

设计应遵循：

- 避免营销式大 Hero 和强推销感文案。
- 避免信息过度拥挤，保持适合长期阅读的节奏。
- 使用温暖但克制的色彩，不让界面被单一色系支配。
- 通过近况、精选内容、最近在读/在做等模块体现生活感。
- 保持文本层级清晰，移动端不出现文字重叠或按钮拥挤。

具体 UI 布局、色彩、组件和动效将在后续 UI 讨论中确定。

## 非功能需求

- 响应式：桌面端和移动端均可正常浏览、检索和阅读。
- 可维护性：作者应能以较低成本新增、修改和归档文章。
- 可扩展性：后续可以扩展 RSS、订阅、评论、专题路径、短想法流和双语内容。
- 可读性：正文排版应适合长文阅读，文章元信息不干扰正文。
- 可发现性：文章应能通过频道、标签、归档和搜索被找到。

## 验收标准

### 首页

- 访问首页时，用户可以在首屏理解站点主人、站点定位和主要内容方向。
- 首页可以进入四个主题频道。
- 首页可以看到精选文章和最新文章。
- 当没有精选文章时，页面仍保持合理展示。

### 频道页

- 四个频道均可访问。
- 每个频道可以展示频道说明和文章列表。
- 频道无文章时有空状态。
- 用户可以从频道文章列表进入文章详情。

### 文章页

- 文章的标题、摘要、频道、标签、发布时间、更新时间可以正常展示。
- 正文内容可阅读，目录可帮助定位内容。
- 用户可以通过前后篇、相关文章或标签继续浏览。
- 移动端阅读时文本不重叠，导航不遮挡正文。

### 搜索与归档

- 用户可以通过关键词搜索文章。
- 用户可以通过标签和频道筛选文章。
- 用户可以通过归档按时间查看文章。
- 搜索无结果时有清晰提示。

### 关于页

- 关于页能简短呈现作者是谁、当前关注什么、最近在读或在做什么。
- 关于页提供联系方式或社交链接位置。
- 关于页不承担完整简历或作品集职责。

## 风险与待确认事项

- 待确认：站点名称、作者署名和一句话介绍。
- 待确认：四个频道的最终命名是否需要更个人化。
- 待确认：首页近况、最近在读/在做模块的具体字段。
- 待确认：文章封面图是否作为常用内容元素。
- 待确认：搜索能力的实现方式将在技术方案阶段确定。

## 里程碑与优先级

### 第一阶段：需求与 UI 方向

- 完成本需求文档。
- 讨论并确定整体 UI 风格。
- 确定首页、频道页、文章页、检索页和关于页的布局方向。

### 第二阶段：基础实现

- 搭建站点基础结构。
- 实现首页、频道页、文章页、检索页、归档页和关于页。
- 建立结构化 Markdown 内容模型。

### 第三阶段：内容与体验完善

- 添加示例文章和真实内容。
- 优化移动端、搜索体验和空状态。
- 补充可访问性、SEO 和部署配置。

### 后续可能扩展

- RSS。
- 邮件订阅。
- 评论系统。
- 短想法流。
- 专题路径。
- 双语内容。
